Recommendations (Priority Order)

1. Fix the 3 failing unit tests

The OrderService is missing validation logic for state transitions and getAllOrders() returns fewer records than expected. These are functional bugs — fix the service logic first.

2. Investigate & remove the hard-coded credential field (S2068 / line 19)

The field BACKUP_DB_PASSWORD in OrderService is a HIGH-probability security hotspot. Credentials should never live in source code — move to environment variables or a secrets manager.

3. Replace java.util.Random with SecureRandom (S2245 / line 116)

If random values are used in any security-sensitive context, java.util.Random is predictable. Use java.security.SecureRandom instead. Also fix the re-instantiation bug (S2119).

4. Replace all System.out.println calls with SLF4J logger (S106 / lines 47, 60, 82, 133)

Four occurrences in OrderService. Replace with private static final Logger log = LoggerFactory.getLogger(...) and use log.info() / log.debug().

5. Disable debug flags before production deployment (S4507 / lines 106, 138)

Two debug features found active. Guard them with a conditional check or remove them entirely from production code paths.

6. Add JaCoCo to the Maven build for coverage reporting

Coverage is reported as 0% because no JaCoCo XML report was found. Add the jacoco-maven-plugin to pom.xml so SonarQube can track test coverage on future scans.

7. Address remaining code smells (S1452, S1172, S112, S1068)

Remove wildcard return type in OrderController, remove unused parameters and the unused password field, and introduce a custom exception class instead of RuntimeException.
